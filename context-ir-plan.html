MiniMax H3-Context-IR 复现方案

6 步简化流水线 · Qwen3.6 + DeepSeek-R1 API · 零 GPU 部署
流水线步数: 6 API 模型: 2 本地 GPU: 0 预估工期: 11 天

1. 背景与概述

H3-Context-IR 是 MiniMax H3 系统的多模态上下文预处理与编排系统，输入是用户编写的 prompt + 音频/视频/图片等参考素材，输出是符合官方 base-en.txt / ref-en.txt 模板的结构化文本（供 H3-Base 直接消费生成视频）。

关键事实：Context-IR 未开源，但输出格式通过官方 Prompt Writing Guide 完整公开。README 明确说 "developers can follow the Prompting Guidance to build their own preprocessing systems"，这意味着复现可行。

架构决策：本地预处理 + API 推理

为节省资源，本方案不再自建 GPU 推理集群，改为：

  • 本地（CPU 即可）：视频帧采样、场景切分、音频转写、音源分离、特征提取等预处理工作 —— 这些是通用开源工具，无需 GPU
  • 云端 API：全部 LLM/VLM 推理（语义提取、跨模态关联、Shot 规划、逻辑校验、格式化输出）通过模型服务 API 调用

官方 Skill 分析

GitHub 仓库 skills/h3-prompt-writing/ 包含：

skills/h3-prompt-writing/
├── SKILL.md                    # 入口：定义 Workflow 和 Output Rules
├── agents/openai.yaml          # Agent 配置
└── references/
    ├── base-en.txt             # Base 模式 Prompt 写作指南
    └── ref-en.txt              # Full-Reference 模式 Prompt 写作指南
官方 Skill 本质上是单阶段 Agent 方案：让 AI 一次性完成全部工作。我们的 6 步流水线是更结构化的工业级方案，官方 Skill 可作为对比基线。

2. 核心设计：6 步简化流水线

首先按输入类型区分任务，再按"提取 → 关联 → 规划 → 校验 → 输出"的顺序处理：

步骤 任务 模态 推理需求 执行方式
Step 0 任务区分（规则引擎） 规则 无 本地规则（无模型）
Step 1 语义提取 多模态 中 qwen3.6-plus API
Step 2 跨模态关联 文本/多模态* 中 qwen3.6 API
Step 3 Shot 分割与描述 纯文本* 中 qwen3.6 API
Step 4 逻辑校验 纯文本 高 DeepSeek-R1 API
Step 5 格式化输出 纯文本 低 qwen3.6 API

* Step 2 默认基于 Step 1 语义描述做文本对齐，必要时可回看原始媒体；Step 3 默认纯文本，若视觉描述信息不足可回看关键帧。

Step 0 任务区分（规则）
输入类型决定任务类型：仅文本 = T2VA；文本+图片 = I2VA；文本+图片+视频+音频 = FL2VA/Ref2VA。纯规则判断，零成本。
Step 1 qwen3.6-plus API
语义提取。新一代视觉语言模型，一次调用同时理解图片/视频帧。音频经本地预处理器（Whisper + 特征提取）转为文本描述后喂入。
Step 2 qwen3.6 API
跨模态关联。基于 Step 1 的语义描述做对齐，必要时回看原始媒体：文本引用 ↔ 具体素材，生成 <Subject N> / <Audio N> 标签。
Step 3 qwen3.6 API
Shot 分割与描述。把生成视频的时间线切分为镜头，逐段描述画面内容、动作、对话、音乐、声音事件。
Step 4 DeepSeek-R1 API
逻辑校验。CoT 推理验证 shot 内容逻辑合理性：主体连续性、时间线因果、音频一致性，Ref2VA 模式下判定 retention 级别。
Step 5 qwen3.6 API
格式化输出。按官方 base-en.txt / ref-en.txt 模板组装最终结构化 prompt，指令遵循能力强、输出稳定。

4. 各阶段详细设计

本地预处理器（CPU 执行）

对 Context-IR 的全部输入（prompt + 图像 + 视频 + 音频）进行统一的多模态预处理，输出结构化 JSON 供 Step 1 消费：

模块工具/模型输出用途
视频帧采样OpenCV / Decord 关键帧序列（~1fps） Step 1 视觉理解
场景切分PySceneDetect 镜头边界时间戳 Step 3 镜头分割参考
语音转写Whisper / SenseVoice 带时间戳文本 + 语种 + 说话人标记 对话内容提取、说话人识别
音源分离Demucs / Spleeter 人声 / BGM / 环境音 / SFX 分离 区分 diegetic 与非 diegetic
音乐特征提取 librosa / CLAP BPM, 调性, 乐器, 风格, 响度曲线 non_diegetic_music 描述生成
声音事件检测 YAMNet / AudioSet 事件类型 + 时间戳（脚步声, 门铃, 风声...） overall_soundscape 描述生成
音色特征提取 SpeechBrain / ECAPA-TDNN 说话人 embedding + 音色描述 Ref2VA 音频参考映射
立体声分析 librosa 左右声道差异、声场宽度 立体声特性描述

Step 0: 任务区分（规则引擎，无模型）

检查输入 content 数组的类型组合，直接映射任务类型：

输入类型组合                           → 任务类型
[text]                                → t2va      (文生视频)
[text, image] (仅首/尾帧)             → i2va      (图生视频)
[text, image, video, audio]           → fl2va     (多模态参考生视频)
[text, image, video, audio] + 保留要求 → ref2va   (带保留分析的参考生视频)

只需遍历输入 content 判断 media_type，不需要 LLM，输出任务类型 + 各素材的角色标记（first_frame / reference_video / voice_timbre 等）。

Step 1: 语义提取

模型: qwen3.6-plus（API）· 输入: prompt + 预处理结果 · 输出: 各素材语义描述 (JSON)

从 4 类输入中提取语义，输出 每个素材独立的结构化描述（与关联解耦，天然支持并行）：

  • prompt → 任务参数、风格、镜头意图、对话/音效/音乐需求、参考引用关系
  • 图像 → 主体、场景、构图、色彩、风格、主体与背景关系
  • 视频 → 关键帧视觉描述、运动、摄影机运动、场景切换
  • 音频 → 转写文本（本地 Whisper 输出）、音色描述、BGM 特征、声音事件
{
  "prompt_analysis": {
    "task_type": "ref2va", "duration": 10, "ratio": "16:9",
    "style": "cinematic", "shots_intent": [...],
    "dialogue_intent": [...], "music_intent": "..."
  },
  "media_analysis": {
    "Picture 1": {"subjects": [...], "scene": "...", "composition": "...", "color_style": "..."},
    "Video 1": {"frames": [...], "motion": "...", "camera": "...", "scene_changes": [...]},
    "Audio 1": {"transcript": "...", "timbre": "calm male voice, medium pitch", "role_hint": "voice_timbre"}
  }
}

Step 2: 跨模态关联

模型: qwen3.6（API）· 输入: Step 1 语义描述（必要时回看原始媒体）· 输出: 对齐映射 + 标签定义 (JSON)

建立文本 ↔ 素材 ↔ 实体之间的引用关系：

  • 将文本引用映射到具体素材（"穿粉色西装的男子" → Video 1 中的 Subject）
  • 生成 <Subject N> / <Audio N> 标签定义
  • 识别音频角色（voice_timbre / bgm / sfx / ambience），关联说话人声音与 Subject
{
  "subject_definitions": [
    "<Subject 1> is the young man in <Video 1>...",
    "<Audio 1> is the voice-timbre reference for <Subject 1> (S1)."
  ],
  "cross_modal_mapping": {
    "text_refs": [{"text": "穿粉色西装的男子", "maps_to": "Subject 1", "source": "Video 1"}]
  },
  "reference_relationships": {
    "Picture 1": {"role": "first_frame", "provides": ["Subject 1"]},
    "Video 1": {"role": "source_video", "provides": ["Subject 1", "Subject 2"]},
    "Audio 1": {"role": "voice_timbre", "provides": ["S1 voice"]}
  }
}

Step 3: Shot 分割与描述

模型: qwen3.6（API）· 输入: Step 2 输出 + 场景切分结果 · 输出: 镜头时间线 + 逐段描述 (JSON)

为待生成视频规划镜头结构，逐段仔细描述每段 shot 包含的内容：

  • 视觉：镜头起止时间、摄影机运动、构图、过渡、主体动作
  • 音频：对话时间点、BGM 起止/淡入淡出、声音事件与画面同步
  • 对齐：参考素材与具体镜头的对齐关系
{
  "total_duration": 10.0,
  "shots": [
    {
      "shot_id": 1, "start_time": 0.0, "end_time": 4.5,
      "camera": "medium wide shot, pushing in slowly",
      "subjects": ["Subject 1"],
      "actions": "...",
      "dialogue": [{"speaker": "S1", "text": "...", "time": 2.0}],
      "bgm": {"time": "0-4.5s", "style": "...", "fade": "in"},
      "sound_events": [{"type": "door_bell", "time": 3.2}],
      "transition": "cut"
    }
  ],
  "reference_alignment": {
    "Picture 1": {"aligns_with": "Shot 1", "time": 0.0}
  }
}

Step 4: 逻辑校验

模型: DeepSeek-R1（API）· 输入: Step 1-3 输出 · 输出: 修正建议 + retention_analysis (JSON)

用 CoT 深度推理保证上一步分析的视频内容逻辑合理：

  • 视觉一致性：同一 Subject 在不同 shot 不"变脸"、场景/服装/光线连续性
  • 时间线逻辑：动作先后顺序、因果链、镜头切换合理性
  • 音频一致性：说话人ID连续、BGM 不突变、音画同步
  • Ref2VA 保留分析：判定每个 Subject/Audio 的保留级别（fully_preserved / partially_preserved / reference / weak_reference；音频为 fully_copy / partially_copy / reference / weak_reference）
  • 缺失补充：推理出参考素材未覆盖的细节（视觉/音频）
{
  "retention_analysis": [
    "<Subject 1> (appears in [Shot 1], [Shot 2]): fully_preserved - ...",
    "<Audio 1>: reference - voice timbre guides dialogue delivery..."
  ],
  "corrections": [
    {"shot_id": 1, "issue": "S1 服装与 Shot 2 不一致", "fix": "统一为深海军蓝西装"}
  ],
  "inferred_details": {
    "missing_visuals": "补充服装颜色为深海军蓝...",
    "missing_sound": "添加环境音：舰桥的低频嗡鸣..."
  }
}

Step 5: 格式化输出

模型: qwen3.6（API）· 输入: 全部前序输出（含修正后）· 输出: 符合官方 base-en.txt / ref-en.txt 模板的最终结构化 prompt (Text)

这是 Context-IR 的最终输出，直接送入 H3-Base 生成视频。System Prompt 基于官方规范编写，确保格式 100% 对齐。

输出字段详解（视觉 + 文本 + 音频统一格式）

Base 模式（3 个字段）：

  • integrated_multimodal_description：按镜头描述的视觉+对话内容，使用 [Shot N] 标记
  • overall_soundscape：1-4 句英文，描述环境音 + 物理动作音（风、雨、脚步声、衣服摩擦等），不含对话和演唱
  • non_diegetic_music：1-3 句英文，描述角色听不到的背景音乐，关注乐器/速度/节奏/力度变化，不使用抽象情绪词

Ref2VA 模式（6 个字段）：

  • subject_definitions：定义 <Subject N> 和 <Audio N> 标签
  • summary：参考素材的生成说明
  • retention_analysis：视觉/音频的保留级别分析
  • detailed_description：含 <Subject N> 和 <Audio N> 引用的详细描述
  • overall_soundscape：同上 Base 模式规则
  • non_diegetic_music：同上 Base 模式规则

音频引用标签示例

<Audio 1>: fully_copy - <Audio 1> is reused 1:1 as the target video's complete final audio track.
<Audio 2>: partially_copy - the atmospheric background music from <Audio 2> is reused in the target video.
<Audio 3>: reference - the target speaker follows <Audio 3>'s voice timbre and measured delivery.

Ref2VA 音频参考完整链路示例

Step 0: 输入含音频 → 任务类型 = ref2va
Step 1: 本地预处理器分析 Audio 1 音色 → "calm male voice, medium pitch, measured delivery"
Step 2: 跨模态关联 → <Audio 1> is the voice-timbre reference for <Subject 1> (S1).
Step 3: Shot 规划 → S1 在 2.0s 处说话，参考 Audio 1 的音色
Step 4: 逻辑校验 → <Audio 1>: reference - voice timbre guides dialogue delivery
Step 5: 输出:
  subject_definitions:
  <Subject 1> is the young man in <Video 1>...
  <Audio 1> is the voice-timbre reference for <Subject 1> (S1).

  retention_analysis:
  <Audio 1>: reference - its vocal timbre guides the dialogue delivery of <Subject 1>.

  detailed_description:
  ... <Subject 1> (S1) speaks in the calm male voice referenced from <Audio 1>: <d>[English] ...</d>

  overall_soundscape:
  ...

  non_diegetic_music:
  ...

9. 关键设计决策

  1. 任务区分规则化：输入类型直接决定任务类型，无需模型推理，零成本
  2. 语义提取与关联解耦，统一 qwen3.6 视觉模型：Step 1 只做素材理解（可并行），Step 2/3 必要时可回看原始媒体做对齐，模型种类减至 2 个（qwen3.6 + DeepSeek-R1）
  3. API 调用替代本地推理：零 GPU 部署，按量付费，开发迭代成本低
  4. 统一 OpenAI 兼容客户端：base_client.py 抽象 provider，可随时切换 DashScope / DeepSeek / 其他平台
  5. 预处理保留本地：转写/分离/特征提取没有现成 API 或 API 成本高，本地 CPU 工具链成熟且免费
  6. Step 4 使用推理模型：逻辑校验是质量上限所在，CoT 推理价值最大
  7. Step 5 System Prompt 直接基于官方规范：确保输出格式与官方 100% 对齐
  8. Ablation 评估机制：逐步骤移除/替换模型，验证每个组件的实际贡献

@dataclass
class PipelineContext:
    # 原始输入
    raw_input: dict  # {content: [text/image/video/audio...], duration, ratio, model}

    # Step 0 (规则引擎)
    task_type: str   # t2va / i2va / fl2va / ref2va
    media_roles: dict  # {素材 id → role: first_frame / reference_video / voice_timbre ...}

    # 预处理结果（本地 CPU）
    preprocessed: dict  # {video_frames, scene_changes, audio_analysis}

    # Step 1 (qwen3.6-plus API)
    semantic_descriptions: dict  # {prompt_analysis, media_analysis}

    # Step 2 (qwen3.6 API)
    cross_modal_mapping: dict  # 跨模态映射
    subject_definitions: list[str]  # <Subject N> / <Audio N> 标签定义

    # Step 3 (qwen3.6 API)
    shot_timeline: dict  # 镜头时间线 + 逐段描述（含视觉/音频元素）

    # Step 4 (DeepSeek-R1 API)
    validation: dict  # {corrections, retention_analysis, inferred_details, consistency_notes}

    # Step 5 (qwen3.6 API)
    final_prompt: str  # 符合官方模板的结构化 prompt
