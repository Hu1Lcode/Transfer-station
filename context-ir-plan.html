MiniMax H3-Context-IR 复现方案

5 阶段多模型流水线 · 基于 Qwen3-VL-32B + DeepSeek-R1 架构
阶段数: 5 模型数: 4 硬件: 4x A100-80G 预估工期: 20 天

1. 背景与概述

H3-Context-IR 是 MiniMax H3 系统的多模态上下文预处理与编排系统，负责理解文本、图像、视频、音频之间的语义关系，输出结构化中间表示供 H3-Base 消费。

关键事实：Context-IR 未开源，但输出格式通过官方 Prompt Writing Guide 完整公开。README 明确说 "developers can follow the Prompting Guidance to build their own preprocessing systems"，这意味着复现可行。

官方 Skill 分析

GitHub 仓库 skills/h3-prompt-writing/ 包含：

skills/h3-prompt-writing/
├── SKILL.md                    # 入口：定义 Workflow 和 Output Rules
├── agents/openai.yaml          # Agent 配置
└── references/
    ├── base-en.txt             # Base 模式 Prompt 写作指南
    └── ref-en.txt              # Full-Reference 模式 Prompt 写作指南
官方 Skill 本质上是单阶段 Agent 方案：让 AI 一次性完成全部工作。我们的 5 阶段流水线是更结构化的工业级方案，官方 Skill 可作为对比基线。

2. 核心设计：每阶段用最适合的模型

阶段 任务 模态 推理需求 推荐模型 GPU
Phase 1 文本解析 + 分类 纯文本 低 Qwen3-8B 1
Phase 2 视觉理解 + 跨模态关联 多模态 中 Qwen3-VL-32B 2
Phase 3 时序规划 + 镜头编排 多模态/文本 中 Qwen3-VL-32B (复用) 2
Phase 4 逻辑推理 + 一致性校验 纯文本 高 DeepSeek-R1-32B 1
Phase 5 指令遵循 + 格式化输出 纯文本 低 Qwen3-32B 1
Phase 1 Qwen3-8B
指令解析本质是文本分类 + 信息抽取，8B 级别足够胜任。不需要视觉能力，用小模型减少 GPU 占用。
Phase 2 Qwen3-VL-32B
唯一必须多模态的阶段。与 H3-Encoder 同源（Qwen3-VL-32B），架构对齐最好。需要看清图像/视频帧中的主体、场景、物体。
Phase 3 Qwen3-VL-32B
可复用 Phase 2 的 VL 实例。如果 Phase 2 输出足够丰富，可退化为 Qwen3-32B（文本版），只需 1 GPU。
Phase 4 DeepSeek-R1-32B
推理最密集的阶段。retention_analysis 需要判断保留级别 + 推理缺失细节 + 校验一致性。DeepSeek-R1 的 Chain-of-Thought 推理能力在此发挥最大价值。
Phase 5 Qwen3-32B
纯文本组装的"格式化"阶段，所有信息已在结构化 JSON 中。需要指令遵循能力强、能严格按格式输出的模型。

4. 各阶段详细设计

预处理（Preprocessor）

对所有输入进行统一的多模态预处理，输出结构化 JSON 供各阶段消费：

模块工具/模型输出用途
视频帧采样OpenCV / Decord 关键帧序列（~1fps） Phase 2/3 视觉理解
场景切分PySceneDetect 镜头边界时间戳 Phase 3 镜头分割
语音转写Whisper / SenseVoice 带时间戳文本 + 语种 + 说话人标记 对话内容提取、说话人识别
音源分离Demucs / Spleeter 人声 / BGM / 环境音 / SFX 分离 区分 diegetic 与非 diegetic
音乐特征提取 librosa / CLAP BPM, 调性, 乐器, 风格, 响度曲线 non_diegetic_music 描述生成
声音事件检测 YAMNet / AudioSet 事件类型 + 时间戳（脚步声, 门铃, 风声...） overall_soundscape 描述生成
音色特征提取 SpeechBrain / ECAPA-TDNN 说话人 embedding + 音色描述 Ref2VA 音频参考映射
立体声分析 librosa 左右声道差异、声场宽度 立体声特性描述

Phase 1: 指令解析

模型: Qwen3-8B · 输入: 用户 text + media 元数据 · 输出: 指令树 (JSON)

从用户输入中提取文本、图像、视频、音频四类信息的结构化描述：

  • 文本/视觉：任务类型、时长、比例、风格、镜头意图、参考图像/视频映射
  • 音频：对话内容与说话人描述、音效/环境音需求、背景音乐风格/情绪要求、音频参考关系（如"音色参考音频1"）
{
  "task_type": "t2va" | "i2va" | "fl2va" | "ref2va",
  "duration": 10,
  "ratio": "16:9",
  "style": "cinematic" | "live-action" | "2D-animated" | ...,
  "shots_intent": [
    {"shot_id": 1, "description": "...", "subjects": [...], "actions": [...]}
  ],
  "references": {
    "images": [{"id": "Picture 1", "role": "first_frame"}],
    "videos": [{"id": "Video 1", "role": "reference_video"}],
    "audios": [{"id": "Audio 1", "role": "reference_audio"}]
  },
  "dialogue_intent": [...],
  "soundscape_intent": "...",
  "music_intent": "..."
}

Phase 2: 跨模态关联

模型: Qwen3-VL-32B · 输入: 指令树 + 原始媒体 · 输出: 跨模态映射 + subject_definitions (JSON)

将文本指令与图像、视频、音频参考进行跨模态对齐：

  • 视觉：识别图像/视频帧中主体，生成 <Subject N> 标签定义，建立文本到视觉的映射
  • 音频：将文本引用映射到具体音频文件，识别音频角色（voice_timbre / bgm / sfx / ambience），生成 <Audio N> 标签，关联说话人声音与 Subject
{
  "subject_definitions": [
    "<Subject 1> is the young woman with long dark hair in <Picture 1>..."
  ],
  "cross_modal_mapping": {
    "text_refs": [{"text": "穿粉色西装的男子", "maps_to": "Subject 1", "source": "Video 1"}]
  },
  "reference_relationships": {
    "Picture 1": {"role": "first_frame", "provides": ["Subject 1"]},
    "Video 1": {"role": "source_video", "provides": ["Subject 1", "Subject 2"]},
    "Audio 1": {"role": "voice_timbre", "provides": ["S1 voice"]}
  }
}

Phase 3: 时序理解

模型: Qwen3-VL-32B · 输入: 指令树 + 映射 + 视频帧 · 输出: 镜头时间线 (JSON)

安排每个镜头的时间顺序，同时处理视觉和音频的时间线：

  • 视觉：镜头起止时间、摄影机运动、构图、过渡效果
  • 音频：对话时间点安排、BGM 起止/淡入淡出时间、声音事件与画面同步、镜头切换时的音频过渡
{
  "total_duration": 10.0,
  "shots": [
    {
      "shot_id": 1, "start_time": 0.0, "end_time": 4.5,
      "camera": "medium wide shot, pushing in slowly",
      "composition": "...",
      "subjects": ["Subject 1"],
      "actions": "...",
      "dialogue": [{"speaker": "S1", "text": "...", "time": 2.0}],
      "transition": "cut"
    },
    {
      "shot_id": 2, "start_time": 4.5, "end_time": 10.0,
      "camera": "close-up, shake strongly",
      "subjects": ["Subject 1"],
      "transition": "cut"
    }
  ],
  "reference_alignment": {
    "Picture 1": {"aligns_with": "Shot 1", "time": 0.0}
  }
}

Phase 4: 逻辑推理

模型: DeepSeek-R1-32B · 输入: Phase 1-3 输出 · 输出: retention_analysis + 推理结果 (JSON)

利用 CoT 深度推理，处理视觉和音频的保留分析与一致性校验：

  • 视觉：Subject 保留级别（fully_preserved / partially_preserved / reference / weak_reference）、缺失视觉细节推理
  • 音频：音频保留标记（fully_copy / partially_copy / reference / weak_reference）、区分 diegetic vs non-diegetic 声音、说话人ID连续性校验、补充缺失的音效/环境音描述
{
  "retention_analysis": [
    "<Subject 1> (appears in [Shot 1], [Shot 2]): fully_preserved - ...",
    "<Audio 1>: reference - voice timbre guides dialogue delivery..."
  ],
  "inferred_details": {
    "missing_visuals": "补充服装颜色为深海军蓝...",
    "missing_sound": "添加环境音：舰桥的低频嗡鸣..."
  },
  "consistency_notes": {
    "speaker_continuity": "S1 在 Shot 1 和 Shot 2 中保持一致"
  }
}

Phase 5: 结构化输出生成

模型: Qwen3-32B · 输入: 全部前序输出 · 输出: 最终结构化 prompt (Text)

System Prompt 直接基于官方 base-en.txt 和 ref-en.txt 编写，确保格式 100% 对齐。

输出字段详解（视觉 + 文本 + 音频统一格式）

Base 模式（3 个字段）：

  • integrated_multimodal_description：按镜头描述的视觉+对话内容，使用 [Shot N] 标记
  • overall_soundscape：1-4 句英文，描述环境音 + 物理动作音（风、雨、脚步声、衣服摩擦等），不含对话和演唱
  • non_diegetic_music：1-3 句英文，描述角色听不到的背景音乐，关注乐器/速度/节奏/力度变化，不使用抽象情绪词

Ref2VA 模式（6 个字段）：

  • subject_definitions：定义 <Subject N> 和 <Audio N> 标签
  • summary：参考素材的生成说明
  • retention_analysis：视觉/音频的保留级别分析
  • detailed_description：含 <Subject N> 和 <Audio N> 引用的详细描述
  • overall_soundscape：同上 Base 模式规则
  • non_diegetic_music：同上 Base 模式规则

音频引用标签示例

<Audio 1>: fully_copy - <Audio 1> is reused 1:1 as the target video's complete final audio track.
<Audio 2>: partially_copy - the atmospheric background music from <Audio 2> is reused in the target video.
<Audio 3>: reference - the target speaker follows <Audio 3>'s voice timbre and measured delivery.

Ref2VA 音频参考完整链路示例

Phase 1: 解析 "音色参考音频1" -> audio_references: [{"id": "Audio 1", "role": "voice_timbre"}]
Phase 2: Preprocessor 分析 Audio 1 的音色 -> "calm male voice, medium pitch, measured delivery"
         生成: <Audio 1> is the voice-timbre reference for <Subject 1> (S1).
Phase 3: 规划 S1 在 2.0s 处说话，参考 Audio 1 的音色
Phase 4: 推理 retention: <Audio 1>: reference - voice timbre guides dialogue delivery
Phase 5: 输出:
  subject_definitions:
  <Subject 1> is the young man in <Video 1>...
  <Audio 1> is the voice-timbre reference for <Subject 1> (S1).
  
  retention_analysis:
  <Audio 1>: reference - its vocal timbre guides the dialogue delivery of <Subject 1>.
  
  detailed_description:
  ... <Subject 1> (S1) speaks in the calm male voice referenced from <Audio 1>: <d>[English] ...</d>
  
  overall_soundscape:
  ...
  
  non_diegetic_music:
  ...
Base 模式输出
integrated_multimodal_description: [Shot 1] Cinematic, ...

overall_soundscape: ...

non_diegetic_music: ...
Ref2VA 模式输出
subject_definitions:
<Subject 1> is ...

summary:
[reference generation] ...

retention_analysis:
<Subject 1>: fully_preserved - ...

detailed_description:
The target video is in ... style.

overall_soundscape:
...

non_diegetic_music:
...

9. 关键设计决策

  1. 每阶段独立选型：Phase 1/5 用轻量模型，Phase 2/3 用多模态模型，Phase 4 用推理模型，各取所长
  2. 阶段间输出为结构化 JSON：便于程序化处理、校验、缓存，也便于跨阶段传递
  3. Phase 5 System Prompt 直接基于官方规范：确保输出格式与官方 100% 对齐
