verl · VeRL-Omni · VeOmni

三个名字，三层分工：verl 是 LLM 的 RL 编排底座；VeRL-Omni 是它在扩散与全模态生成模型上的专项扩展（建立在 verl + vLLM-Omni 之上）；VeOmni 是任意模态的训练框架，同时充当 VeRL-Omni 的可选训练后端。三者拼成「训练 → RL 对齐 → 推理部署」的一条完整链路。

VeOmni 负责「把全模态模型训起来」，verl 负责「RL 怎么编排」，VeRL-Omni 把两者与 vLLM-Omni 组装成「扩散 / 全模态生成模型的 RL 后训练」——训练后端三选一，rollout 一律走 vLLM-Omni。

③

verl：RL 编排底座

Volcano Engine Reinforcement Learning for LLMs · 字节 Seed 发起，verl 社区维护 · Apache-2.0

一句话

verl 把 RL 后训练拆成「数据流编排」与「并行执行」两层：用单控制器写数据流，用多控制器（SPMD）跑并行，从而几行代码就能组装 GRPO / PPO，并自由更换训练与推理引擎。

三个设计支柱

混合控制器编程模型单控制器描述 RL 数据流，多控制器执行并行计算；复杂后训练流程可灵活表达
+
模块化 API计算与数据依赖解耦，无缝接入 FSDP、Megatron-LM、vLLM、SGLang
+
3D-HybridEngineactor 重分片，消除显存冗余，大幅降低「训练 ↔ 生成」切换的通信开销

其他要点

  • 灵活的设备映射：不同模型可放到不同 GPU 组，适配不同规模集群。
  • HuggingFace 模型开箱可用，降低接入成本。
  • 设备无关性：NVIDIA / AMD ROCm / Ascend NPU 均有支持路径。

围绕 verl 长出的生态

verl 已经不只是「一个 RL 库」，而是 verl-project 组织下的一片子项目森林：

子项目定位
VeRL-Omni扩散与全模态生成模型的 RL 后训练（本页主角之一）
verl-vla统一的 VLA 后训练框架：人机在环数据采集、SFT 与 RL，覆盖仿真器 / 真机 / 云边分布式资源
uni-agent规模化构建、运行与训练 LLM Agent 的统一框架

verl-SpeCoRL 训练与推理的投机解码协同训练，让 draft 模型在训练中持续对齐、可直接复用于加速服务
RL-InsightRL 训练在线可观测性：训练侧指标、RL 状态 trace 与服务看板打通
VeRL-Tinker沿用 Tinker Cookbook 的使用习惯，在你自己掌控的 GPU worker 上跑 SFT / RL / 蒸馏

VeRL-Omni：扩散与全模态的 RL

Easy, fast, and stable RL training for diffusion and omni-modality models · built on top of verl + vLLM-Omni

为什么需要它单独成库

多模态生成 RL 与纯文本 LLM RL 的差别不只在模型结构：rollout 是连续 latent 空间里的去噪轨迹（不是 token 序列），一次 rollout 可能串起 text encoder → DiT → VAE 多级异构流水线，奖励函数本身常常就是多模态模型，显存峰值也高得多。这些约束值得一个专门的仓库来快速演进。

⑤

VeOmni：任意模态训练框架

VeOmni: Scaling Any Modality Model Training with Model-Centric Distributed Recipe Zoo · 字节 Seed · 论文 OmniScale 被 AAAI 2026 接收

核心理念

Model-centric，而不是 system-centric：把复杂的分布式并行逻辑从模型计算里解耦成一份份可组合的「recipe」。研究者只需按 HuggingFace 风格写模型，就能像搭积木一样组合出高效的并行训练配方——官方称可把工程时间压缩 90% 以上。

设计原则

灵活与模块化

  • 组件可解耦、可替换成你自己的实现。
  • Trainer-free：提供线性训练脚本，不用 PyTorch-Lightning / HF Trainer 那种刚性结构，训练逻辑完全暴露，透明可控。
  • 同时提供一个基础 trainer（文本 / VLM / omni），以及作为 RL 训练后端的 rl trainer。

Omni native + Torch native

  • 任意 omni 模型都能跨设备、跨加速器扩展。
  • 最大程度复用 PyTorch 原生能力，兼容性与性能兼得。
  • 支持预训练与后训练（single- 与 multi-modal 均可）。

关键特性

FSDP2 训练后端 序列并行（DeepSpeed Ulysses，async / non-async） 专家并行（MoE，如 Qwen3-MoE） MoE 高效 GroupGemm kernel · Liger-Kernel 动态批处理 + Omnidata 数据处理 Torch Distributed Checkpoint NVIDIA GPU / AMD ROCm / Ascend NPU 兼容 HuggingFace Transformers wandb 实验追踪

它和 RL 的关系（这是三者交汇点）

  • VeOmni 自我定位是训练框架，但它自带一个 rl trainer，可充当 RL 训练后端。
  • 路线图里明确写着 “RL post training for omni-modality models with VeRL”——即与大模态 RL 框架对接。
  • 在 VeRL-Omni 侧则体现为训练后端三选一中的一项：run_qwen_image_ocr_veomni.sh（64×H100）。
  • 两者共享同一批底层能力（FSDP2、序列并行、专家并行、HF 权重格式），因此可以互换而不必重写模型代码。
